### 1.2 SHAKY — measured, but the control is missing, the metric is confounded, or n=1

**S1 — "The across-cycle spread (2.66) is CORRECT because MS1 FWHM is 2.61 cycles."**
Arithmetically true, mechanistically unsupported. `assembleFromList_` sets `out.setRT(pc.rt)` once
(`src:1138`); `pc.rt` is a single scalar per trace (`src:862`, `:929`, `:173`). There is one
spectrum per hypothesis and **no per-cycle emission anywhere in the source** — 2,145,053 hypotheses
→ 1,528,058 spectra confirms ~1:1. So 2.66 is 2.66 *distinct traces* whose centroids land in
distinct 1.385 s bins, not one peak sampled 2.66 times across its elution profile. `merge-design.md:312-315`
says the same thing independently. **Downgrade `fwhm-s30.md:33-36,42` to "consistent with;
mechanism unmeasured."**

**S2 — The redundancy magnitude.** The repo publishes **three mutually inconsistent values** of its
own headline number:

| value | source | acceptance procedure |
|---|---|---|
| 9.51 / 1.69 (→ 5.6×) | `README.md:65`, `joint-2026-07-22.md:19` | **two separate acceptance sets** (`joint_bench.py:176-177` calls `target_decoy_fdr` on PSMs and on peptides independently, then divides) |
| 7.57 / 1.62 (→ 4.67×) | `cycle-redundancy.md:17` | one PSM-level set, peptides derived from it |
| 8.98 / 1.66 (→ 5.41×) | `dataset D-BASELINE.md:15` — the **frozen decision file** | — |

`merge-design.md:331,487-488` already establishes that 9.51/1.69 is a mixed-acceptance-set artefact
and that the single-set value is 4.67×. The correction was written and never applied. The 18 %
overstatement is computed on dataset B only; **no single-set value exists for dataset A or dataset D, so the size of
the correction on the three-sample headline is not known.**

**S3 — "38 % fewer PSMs at zero peptide cost" (split14).** Not a PSMs/peptide measurement. The
scorer at `scratchpad/run_e_extract.sh:48-55` increments `n` for **every row** of
`results.sage.tsv` — decoys and sub-threshold rows included — while peptides are filtered at
`peptide_q ≤ 0.01`. The peptide move (10,072 → 10,076, +0.04 %) is inside the 0.06 % floor.

**S4 — The FWHM-relative valley-splitting sweep (−19.6 / −5.9 / −5.3 % at 1×/2×/4×).**
`trace:split_valleys_fwhm` assigns to `ms2_split` (`src:1380-1388`), consumed only at `src:1607` for
**fragment** tracing. MS1 tracing has already finished at `src:1330-1331` reading
`trace:ms1_split_valleys` directly, and `run_next.sh:35` pinned `-trace:ms1_split_valleys 7.0` on
every arm. **The sweep varied the MS2 window with MS1 held constant.** The conclusion drawn from it
— "7.0 s absolute is near-optimal on both a 31 min and a 5.6 min gradient" — is an MS1 claim from an
MS2 experiment. Retract the conclusion. The help string at `src:513` ("Overrides
`trace:ms1_split_valleys` when > 0") is also false.

**S5 — Charge agreement 74.6 % vs a 69.6 % constant.** `harness/collate.py:112-118` filters
candidates to `|Δm/z| ≤ 20 ppm` **before** counting charge agreement. SpeXtract infers charge and
monoisotope jointly (`src:783`, `:841`, `:875`), so a joint charge+monoisotope error moves m/z by
~1/z Da (>400 ppm at m/z 600) and is **silently dropped from the metric that exists to count charge
errors**. A pure charge error with a correct monoisotope does not move m/z and *is* counted. So
74.6 % is an upper bound on a restricted population. dataset B only.

**S6 — `max_fragment_charge=1` (+1.1 % dataset D, +0.35 % small file).** Appears in **no file in the
repository**; all three committed Sage configs still carry `max_fragment_charge: 2`. It is a
*search-time* setting — SpeXtract's output is byte-identical under it — so it moves the referee, not
the tool. No MSFragger confirmation exists, against the repo's own policy
(`search-engine-policy.md:24-25`, `dataset D-BASELINE.md:30-31`). Adopting it also invalidates the frozen
10,072 reference, which was set at `max_fragment_charge 2`.

**S7 — MS1 band-parallel tracing (319 → 123 s, 2.6×).** The speedup is measured. It is **not
output-identical**: 4,915,724 vs 4,915,697 traces, 2,145,165 vs 2,145,049 precursors. It is listed
in the repo's own docs as **B1, behaviour-changing, must be benchmarked** — and the quality gate
never completed. Counting it as a "confirmed win" is a category error.

**S8 — 86.9 % / 80.4 % as a measure of value.** The measurement is sound; the *interpretation* is
the problem. Both arms are closed search against a DIA-NN-shaped reference (tryptic, z2–4, ≤2 mods),
which **structurally cannot contain the open-search target class the tool exists to find**. This
number measures how well SpeXtract does the reference implementation's job, not whether it does its own.

- `sage_open.json` sets `da: [-150, +500]` → `dm ∈ [−500, +150]`. The discovery side for genuine

## 2. THE HONEST ASSESSMENT

The engineering is converging and the scientific claim is not, and those two facts are being
conflated. Three wins against roughly fifteen falsifications in three days is a *healthy* ratio for
genuine exploration — falsifying twelve bad ideas cheaply is the process working, and the merge
programme in particular was killed properly, three independent ways, with both of the author's own
mechanistic hypotheses refuted by data rather than abandoned quietly. What is not healthy is that the
retraction pattern is stable and still live: all three public retractions have the identical
form — a metric published without its null or its control — and at HEAD today the repo still
publishes a falsification of an unreachable parameter, a superseded reproducibility figure that its
own docs list as rejected, three mutually inconsistent values of its headline redundancy number, a
"three independent benchmarks" claim whose three arms share an engine, an mzML and a FASTA and one of
which has no provenance at all, and an entrapment number quoted in direct violation of the gate the
project itself wrote in capital letters. Worse, the one instrument built to measure the thing the
tool exists for is oriented so that the artefact it was built to detect is reportable only below m/z
501, while its positive-control script injects the mirror error — so "the control did not fire" was
never actually established and the assay has never been run in the direction that matters.
Meanwhile a third undocumented scoring-parallelism change is live in `main`, committed inside a
merging commit, postdating the frozen baseline, so **no benchmark number in this repository
describes the binary it ships**. The project is not thrashing on ideas. It is thrashing on
bookkeeping, and in a project whose only durable output is measurements, that is the same thing.

### 1. Fire the charge positive control in **both** directions, in the unchanged wide window

**Experiment.** Take one working mzML. Run `bench/corrupt_charge.py` twice on it —
`--from-z 2 --to-z 4` and `--from-z 4 --to-z 2` — at the same `--fraction`. Search **both** outputs
under `bench/sage_open_wide.json` **unchanged**. Score both with `bench/open_bench.py`. Record the
recovery rate as a function of m/z, and commit the results to `docs/benchmarks/`.

**Prediction, from U5.** The 2→4 arm (`dM = +1198`) recovers across m/z 327–1501. The 4→2 arm
(`dM = −1198`) recovers only below m/z 501 and collapses to near zero overall. That asymmetry is the
direct experimental proof that the window is inverted.

**Cost.** 0.5 person-days. 2 Sage runs on the small file (~5 min compute) plus two mzML rewrites. No
new code — the script and the config already exist.

**Expected gain.** Decides whether the project has *any* instrument for its own purpose. Unblocks or
kills every open-search number published to date, the "three independent benchmarks" claim, the
2.82×/1.05× figure, and the choice between correcting the window (cheap) and abandoning delta-mass
ray geometry entirely (expensive but necessary).

**Result that would kill it.** Both arms recover at similar rates — high or low. High-and-symmetric
means the window was never the problem and U5 is wrong; low-and-symmetric means the instrument is
blind for a reason no window change fixes, and the delta-mass assay must be abandoned outright
rather than repaired. Either symmetric outcome retires U5 and forces the ddaPASEF route or nothing.

**Do not** correct the `da` bounds before this run. Correcting first destroys the control.

**Cost.** 0.25 person-days to register + 2–4 person-days to build the matcher and the comparison.

### 5. The last upstream redundancy lever — pre-registered as a probable loss

**Experiment.** Two arms on dataset D, one axis each: (a) `-assembly:dedup_precursors` on; (b) a genuine
drop of the 48.7 % isotope-unsupported hypotheses (the code that the `src:1408` comment falsely
claims already exists). Score peptides and single-set PSMs/peptide.

**Pre-registration, stated before the run because the prior is bad.** `dedupPrecursors_` **erases**

**Cost.** 0.5 person-days, 2 × 74 min extraction + 2 Sage runs.

**Expected gain.** Low probability, high payoff. If either arm holds peptides within the 0.06 %
floor while cutting single-set PSMs/peptide materially, that is the first real redundancy win. If
both lose ≥1 %, the redundancy question is closed and moves to §4.

**Result that would kill it.** Peptides fall ≥1 % on either arm → falsified, and **redundancy is
reported as a property of the emission model, not pursued as a defect.**

**A1 — Post-hoc merging and consolidation, in every form.** Measured three ways: coordinate gate
−3.71 / −7.58 / −14.66 % at 1.4 / 2.6 / 5.0 s; max-instead-of-sum a further −11 points; cosine ≥ 0.85

## 5. THE ONE THING

**Run `bench/corrupt_charge.py` twice on one mzML — `--from-z 2 --to-z 4` and `--from-z 4 --to-z 2` —
and search both under `bench/sage_open_wide.json` unchanged. One afternoon. Two Sage runs. No new
code. Commit the results to `docs/benchmarks/`.**

Why this and nothing else:

The project exists to enable **blind/open search**. Every number it publishes is **closed** search
against a reference that structurally cannot contain the target class. The one instrument built to
bridge that gap has a positive control that surfaced 26 of 10,199 known events — and that "failure"
was never actually established: against the assay's own acceptance rate (1,175 / 1.35 M), the
proportional expectation was **8.9**, so 26 is 2.9× *above* it, and no power calculation exists.
Meanwhile the wide window is oriented so that the artefact it was purpose-built to see
(`dM = −1000 … −2800`) is reportable only at **m/z ≤ 501**, while `corrupt_charge.py`'s default
direction injects the **mirror** error (`dM = +1198`), which the window *can* see out to m/z ≤ 1501.

That means running the control as configured today would return **high** recovery and be read as
"the assay works" — falsely vindicating an instrument that never covered the real direction. The
two-arm run is the only cheap experiment that separates *the assay is blind* from *the window points
the wrong way*, and it must happen **before** the `da` bounds are corrected, because correcting them
first destroys the control.

Everything downstream forks on the answer. Symmetric recovery → the window was never the problem, the
delta-mass assay is dead, and the ddaPASEF route (step 4) or the write-up (step 6) is the whole
remaining programme. Asymmetric recovery → correct the bounds to report `dm ∈ [−2800, +200]`, re-run
every open-search number, and the project's central claim becomes testable for the first time.

It costs half a day. Nothing else on this list is worth doing until it is done.
